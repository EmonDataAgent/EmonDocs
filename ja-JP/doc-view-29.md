## 1. 概要

### 1.1 機能の概要

スケジュールタスクは Agent 自動化機能のコアモジュールです。設定済みの Agent に対して、周期的にトリガーされるバックグラウンドタスクを追加できます。これにより、ユーザが能動的に質問しなくても、Agent が自動的にデータの集計、レポートの生成、異常時のアラートなどの操作を実行できます。結果は複数チャネルを通じてターゲットユーザにプッシュされ、業務分析を「受動的な応答」から「能動的なサービス」へとアップグレードします。

### 1.2 利用シーン

- 日常のデータを定期的に収集・整理し、関連する業務担当者や管理者にターゲットを絞って配信・プッシュします。
- 日報、週報、月報、年報などの各種定期統計レポートを自動生成します。
- データの変動をリアルタイムで監視し、異常時のアラートを迅速にトリガーしてメッセージプッシュを完了させます。

### 1.3 効果のデモ

営業シーンにおいて、定期的に営業リスクのアラートをプッシュする例。

## 2. 設定手順

### 2.1 設定へのアクセス

スケジュールタスクは、以下の 2 つの場所から設定できます：

#### 2.1.1 管理システム（Agent 設定画面）

「管理システム > Agent 設定画面 > スケジュールタスク」モジュールにアクセスし、「+」ボタンをクリックして新規作成プロセスに入ります。

#### 2.1.2 フロントエンド（Agent 利用画面）

フロントエンドで Agent を利用する際、左側のナビゲーションバーにある「スケジュールタスク」メニューをクリックし、現在の Agent のスケジュールタスク管理画面にアクセスします。

### 2.2 スケジュールタスクの作成

スケジュールタスクの作成には、ゼロから新規作成する方法と、推奨テンプレートを使用して新規作成する方法の 2 種類があります。

#### 2.2.1 ゼロからの新規作成

明確なカスタマイズ要件がある場合に適しています。すべての設定項目を手動で入力する必要があります。「スケジュールタスクの追加」ダイアログで「ゼロから開始」カードをクリックし、タスク設定フォームに入ります。

#### 2.2.2 テンプレートからの新規作成

現在、以下の 2 種類のシーンテンプレートを提供しています。テンプレートには構造化されたタスクのプロンプトとデフォルトの実行頻度が含まれており、ユーザはテンプレートの内容を適切に変更し、プッシュ先のユーザとチャネルを追加するだけで作成が完了します：

- 経営週報
- データアラート

### 2.3 タスク設定項目の説明

タスク設定項目には以下の内容が含まれます：

| 設定項目 | 必須 | 説明 |
| --- | --- | --- |
| スケジュールタスク名 | 必須 | タスクの識別名です。「店舗売上分析日報」など、タスクの目的を明確に表現する名称を使用することをお勧めします。 |
| タスクプロンプト | 必須 | Agent がタスクを実行する際に受け取る完全な指示で、Agent の動作と出力内容を決定します。詳細は後述の「プロンプト作成ガイド」をご参照ください。 |
| 実行頻度 | 必須 | タスクを自動実行する期間と具体的な時間。 |
| プッシュ先ユーザ | 必須 | タスクの実行結果をプッシュする対象ユーザ。特定のメンバーを選択できます。 |
| プッシュチャネル | 任意 | タスク実行結果のプッシュチャネル。プラットフォームや企業 WeChat をサポートし、複数選択が可能です。 |

注：現在、メッセージプッシュはプラットフォームおよび企業 WeChat のみをサポートしています。その他のチャネルは今後順次公開される予定です。

#### 2.3.1 スケジュールタスクプロンプト作成ガイド

構造が整ったプロンプトには、タスク目標、コアルール、および出力要件の 3 つの部分を含める必要があります。

| スケジュールタスクプロンプトの構造テンプレート |
| --- |
| タスク目標：[Agent が完了すべきコアタスクを 1 文で記述する]<br><br>コアルール：<br><br>1. [ルール 1：Agent が分析または処理すべきコアコンテンツを明確にする]<br><br>2. [ルール 2：Agent が詳細に分解または比較すべきディメンションを明確にする]<br><br>3. [ルール 3：Agent が識別または判断すべき方向性を明確にする]<br><br>出力要件：<br><br>1. タイトル：[出力コンテンツのタイトル形式を規定する]<br><br>2. 内容：[出力コンテンツがカバーすべき範囲を規定する]<br><br>3. トーン：[出力コンテンツの言語スタイルや表現方法を規定する] |

| プロンプトの例：経営週報タスク |
| --- |
| タスク目標：今週の業務データに基づき週報を作成し、業務の進捗状況、コアとなる課題、および改善提案を明確に提示する。<br><br>コアルール：<br><br>1. コア指標の振り返り：今週の【売上】など、コア指標の達成状況。<br><br>2. 重点業務分析：貢献上位 3 つのチャネル/地域/カテゴリーを分解し、成長/低下の主な原因を分析する。<br><br>3. リスクと機会の識別：今週の業務における潜在的なリスクを識別する。<br><br>出力要件：<br><br>1. タイトル：【XXビジネスライン】経営週報<br><br>2. 内容：コアルールに記載されたすべての内容を提示する。<br><br>3. トーン：簡潔で専門的に。結論を先に記述し、データで意見を裏付け、冗長な説明は避ける。 |

## 3. 注意事項

1. スケジュールタスクは「対話サブスクリプション」機能に依存しているため、スケジュールタスクを設定する Agent に同機能を追加しておく必要があります。
2. 「管理システム > Agent 監視 > スケジュールタスク」から、すべての Agent のスケジュールタスクを管理できます。
3. 少なくとも 1 つのチャネルをチェックする必要があります。そうしないと、タスクの実行結果がユーザに届きません。
4. 企業 WeChat のプッシュを使用する前に、「IM ツールの連携」モジュールで企業 WeChat の連携設定を完了させる必要があります。そうしないと、プッシュが有効になりません。
5. 「管理システム（Agent設定画面）」から追加されたスケジュールタスクは、「Agent内設定」としてマークされます。「フロントエンド（Agent利用画面）」から追加されたものは、「自分が追加」としてマークされます。
